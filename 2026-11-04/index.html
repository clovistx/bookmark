computer use · agentes · @darrenjr · @evertjr

O computer use ganhou velocidade de vídeo: o voxl transmite o desktop a 60 fps, e o Maestri passa a dividir o seu computador com os agentes

Dois lançamentos da mesma terça atacam os gargalos de quem põe agentes para mexer em telas de verdade: a lentidão do remote desktop e a disputa pelo mouse com quem está trabalhando.

Terça · @darrenjr · @evertjr · mais de 3 mil bookmarks no post do voxl

Darren Baldwin (@darrenjr), cofundador e CTO da Tembo, apresentou o voxl, um remote desktop streaming escrito em Rust que funciona em macOS, Windows e Linux. O vídeo de lançamento coloca lado a lado o mesmo Doom rodando via noVNC, a 11 fps, e via voxl, a 60 fps. O desktop viaja como H.264 por um único WebSocket e é decodificado no navegador com WebCodecs, o que permite atravessar reverse proxies, túneis e URLs de preview de sandbox sem TURN server nem porta UDP. Para agentes, o projeto já traz as APIs /screenshot, /record e /wait, e com isso o stream deixa de ser só uma janela para humanos e vira um ambiente de computer use.

O próprio README é franco sobre a troca: como tudo passa por TCP, uma rede que perde pacotes segura os frames seguintes, enquanto o WebRTC conseguiria pular adiante. Na mesma terça, o brasileiro Evert Junior (@evertjr) anunciou que o Maestri, o canvas infinito em que Claude Code, Codex e OpenCode trabalham lado a lado, agora também tem computer use. Ele escreveu do zero um driver otimizado para Mac, Windows e Linux, com a ideia de que o computador passe a ser compartilhado: os agentes controlam apps com precisão sem tirar o cursor de quem está usando a máquina. No vídeo, um agente preenche uma planilha de orçamento no LibreOffice e outro desenha um foguete no Excalidraw, cada um com o próprio cursor identificado na tela.

Juntos, os dois lançamentos apontam para onde o computer use está indo, com menos screenshot a cada passo e mais sessão contínua, rápida e dividida entre gente e agente. O voxl é open source sob licença MIT e o Maestri tem plano gratuito com um workspace, então dá para comparar as duas abordagens ainda hoje.

O Appllama quer tirar a cara de slop dos apps feitos por agentes, copiando o que já fatura na App Store

O Appllama é uma biblioteca com mais de 85 mil telas de cerca de 1.850 apps iOS entre os que mais faturam, organizadas por onboarding, paywall e fluxo, com a receita estimada de cada app ao lado. Jaimin (@jaimintf) lançou junto um MCP, que deixa o agente estudar essas telas, e um repositório de agent skills que transforma os padrões encontrados em telas mobile com acabamento nativo. front-end · skeleton · @lochieaxon

O Skullet desenha os skeletons sozinho, medindo o próprio componente

Lochie Axon (@lochieaxon) publicou o Skullet, uma biblioteca de loading states que dispensa os placeholders desenhados à mão. Ela renderiza dados de exemplo de forma invisível, mede cada elemento e desenha o skeleton naquele formato, então basta envolver o componente com <Skeleton> para acabar com o layout shift. Não há build step extra, o conteúdo que vem do SSR aparece sem flash de loading e as imagens entram com uma transição suave enquanto carregam.

O FileOS quer ser o Finder que o Mac nunca teve, e chega na semana que vem

Ankur Sehrawat (@Ankur_Sehrawatt) anunciou o lançamento do FileOS, uma alternativa ao Finder que ataca três dores de uma vez: a pasta Downloads bagunçada, o disco cheio e os arquivos de projeto espalhados. O app organiza Downloads em um clique, sugere limpezas e libera espaço com opção de Undo, reúne cada projeto numa página e abre duas pastas lado a lado. A compra é única, de US$ 9,99 no lançamento, e o site já mostra o app funcionando com workspaces por projeto.

Hora do Hands-on

três testes de dez minutos · pra quarta
teste 1 · remote desktop

Um desktop Linux no navegador com o voxl

Numa VM ou num servidor com Xvfb, instale o voxl com cargo install voxl-server e rode DISPLAY=:1 voxl para receber o link de acesso. Abra esse link com ?stats no fim para ver o FPS na tela e chame o endpoint /screenshot para sentir como um agente enxergaria aquele desktop.

teste 2 · skeleton

Troque um loading state feito à mão pelo Skullet

Instale com npm i skullet num projeto React, Vue ou Svelte, envolva com <Skeleton> um card que busca dados e apague o placeholder antigo. Simule uma rede lenta no DevTools e confira se o skeleton tem o formato do conteúdo e se o layout fica parado quando os dados chegam.

teste 3 · os cinco passos

Passe uma rotina do seu time pelo algoritmo do Musk

Escolha um processo que se repete toda semana, como um relatório ou um deploy, e anote cada requisito com o nome de quem pediu. Corte pelo menos uma etapa antes de pensar em ferramenta, e só no fim decida se o que sobrou merece automação.
