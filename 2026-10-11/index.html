O Tov escreve como TypeScript, compila via C e promete binários mais rápidos que os do Rust, tudo pensado para coding agents

É uma linguagem experimental em que o compilador devolve ao agent a correção pronta, e o que vai para produção é um único binário nativo de poucos KB.

Sábado · @richiemcilroy

Richie McIlroy (@richiemcilroy), fundador do Cap, o gravador de tela open source, postou o link do tov.sh com um “wtf who made this”, mas o próprio site assina o projeto como obra do time do Cap. O Tov lê a sintaxe e os tipos do TypeScript, com int e f64 separados e as APIs de Bun e Node, e corta o que costuma confundir: não existe any, null nem ==, e toda chamada que pode falhar precisa ser marcada com try. O checker, escrito em Rust, transforma o programa inteiro num arquivo C, que o clang compila junto com um runtime próprio, sem garbage collector e com a contagem de referências escrita no próprio código gerado.

O detalhe que justifica o rótulo “para agents” é o tov check --json: cada erro vem com código, posição e, quando a correção é óbvia, o edit exato marcado como “safe”, que o agent aplica sem precisar interpretar mensagem de compilador. Nos benchmarks publicados, medidos num M4 Max, um servidor JSON em Tov atende 242 mil requisições por segundo num único core, contra 216 mil do Rust com axum e 111 mil do Bun, usando 1,6 MB de memória; o compile leva 42 ms e o binário stripped fica em 33 KB. O time também testou a linguagem dentro do Cap, com um encoder H.264 escrito em Tov que saiu, em média, 5,2 vezes mais rápido que o x264 no preset veryfast em gravações de tela.

A versão é a 0.0.1, marcada como experimental, e ainda faltam suporte a Windows, gerenciador de pacotes próprio, enums e tuplas, então ninguém deveria migrar um backend para ela agora. O experimento que faz sentido é o que o site sugere: colar no teu agent o prompt pronto, que instala o compilador, lê o llms.txt e passa a rodar tov check --json depois de cada edit, e pedir um CLI pequeno ou um endpoint HTTP para ver quantas voltas ele precisa até o binário sair.

Claude Code · prompt cache

Se o limite do Claude Code anda evaporando, o culpado pode ser o cache de cinco minutos dos subagents

Gabriel Buzzi (@gabrielbuzziv) chamou atenção para um detalhe que Lydia Hallie (@lydiahallie), da Anthropic, confirmou numa resposta: na assinatura, o chat principal do Claude Code guarda o prompt cache por uma hora, mas os subagents, assim como o billing por API, ficam com apenas cinco minutos. Na prática, um subagent que passa mais de cinco minutos parado relê o contexto inteiro na volta e consome o limite de novo. A correção é uma linha no ~/.claude/settings.json, "subagentPromptCacheTtl": "1h", e existe também o promptCacheTtl para a sessão principal. O próprio Gabriel avisa que gravar cache de uma hora custa mais, então a mudança compensa em orquestrações longas, com subagents que vão e voltam, e não em tarefas rápidas.

Neural Engine · Core AI

O System 1 da Anemll faz um modelo de 0.8B decidir em milissegundos no Neural Engine, sem gerar texto

A Anemll (@anemll), projeto open source dedicado a rodar modelos no Apple Neural Engine, publicou o System 1, que usa o Core AI da Apple para tomar decisões numa única forward pass. Em vez de gerar uma resposta e depois fazer parse do texto, o modelo devolve uma probabilidade para cada opção possível, como as rotações e colunas de uma peça de Tetris ou a próxima direção no Snake. As demos rodam o Jeff, um fine-tune do Qwen3.5-0.8B, e adapters treinados com o Unsloth, e no frame do vídeo cada jogada do Snake sai em cerca de 65 ms. A mesma lógica serve para qualquer router ou classificador dentro de um agent, e o código das demos, incluindo a de text routing, já está no GitHub.

Arquivos e ligações

macOS · arquivos

O Homy quer ser o Finder que mostra as coisas, e não só o nome dos arquivos

Mohit Vaswani (@hii_mohit) lançou o Homy, um file browser nativo para Mac, feito em SwiftUI, que organiza imagens, vídeos, músicas, documentos, arquivos compactados e apps em prateleiras com thumbnails grandes. A busca aceita linguagem natural, como “pdfs from last week over 5 mb”, e mostra em chips como entendeu o pedido; o app também lê o texto dentro de screenshots com o Vision framework, agrupa downloads pela origem, de Gmail a WhatsApp, e encontra duplicatas pelo conteúdo. Tudo roda localmente, sem conta nem upload, e o que sai vai para a Lixeira em vez de ser apagado de vez. Custa US$ 9 em pagamento único para os primeiros 200 compradores e US$ 29 depois, e o teste mais revelador é apontá-lo para a pasta Downloads e ver quanto espaço ele propõe liberar.

Grok Bot · voz

Daniel Lafraia pôs o Grok Bot para ligar para um hotel, com voz em tempo real

Numa conversa com Deborah Folloni (@dfolloni) e Glaucia Lemos (@glaucia_lemos86), a mesma do time de Grok Bots que saiu na ed. 36, Daniel Lafraia (@lafraia), do Vagalume e da Panda Video, mostrou um vídeo em que pediu ao Grok Bot para gravar uma ligação de teste para a recepção de um hotel. Segundo ele, a chamada sai por VoIP e a voz é a da OpenAI em tempo real, enquanto a tela mostra quem está falando, se o humano ou a AI. A Deborah logo perguntou se ele paga pelo número e pelo sandbox, que é justamente a conta que separa a demo do uso diário. Para quem já usa o Grok Bot, o caminho prudente é reproduzir o fluxo numa ligação de baixo risco, como confirmar o horário de um restaurante, antes de confiar a ele uma reserva de verdade.
