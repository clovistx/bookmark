O Cursor lança o Agent SDK e passa a tratar agentes como código

Com o SDK, o prompt mora num arquivo Markdown, as tools são escritas em TypeScript e cada mudança pode ser medida por evals embutidos.

Segunda-feira · @cursor_ai · Agent SDK

O Cursor (@cursor_ai) anunciou na segunda-feira que o Agent SDK está disponível. A proposta é definir agentes como código: os prompts ficam em arquivos Markdown, as tools são escritas em TypeScript, e o agente passa a ser versionado e revisado como qualquer outra parte do projeto. Na hora do deploy, dá para usar a infraestrutura hospedada do próprio Cursor ou rodar tudo na sua.

A peça que mais chama atenção são os evals embutidos, que permitem medir o efeito de cada mudança e melhorar o agente ao longo do tempo. Isso ataca um dos problemas mais chatos de quem mantém agentes em produção, que é saber se o ajuste de ontem no prompt melhorou ou piorou o resultado. O post passou de 1.800 bookmarks no X, e o vídeo de lançamento mostra um painel de runs por time e automações agendadas na nuvem.

Deborah Folloni lista os seis ingredientes que seus posts virais sempre têm

Deborah Folloni (@dfolloni) conta que não lembra de nenhum post dela que tenha viralizado sem pelo menos um destes requisitos: moeda social, gatilhos, emoção, visibilidade, valor prático e histórias. O primeiro, segundo ela, explica por que novidades de IA circulam tanto, já que a gente compartilha o que faz a gente parecer mais esperto e mais informado. Os seis vêm do framework STEPPS, apresentado no livro Contagious, que ela recomenda para quem ainda não conhece.

teste 2 · Agent SDK

Um agente mínimo escrito com o Agent SDK

Crie um agente com um prompt curto em Markdown e uma única tool em TypeScript, por exemplo uma que liste os arquivos alterados no último commit. Rode localmente, ajuste uma frase do prompt e use os evals embutidos para ver se a mudança melhorou ou piorou a resposta.

Um post antigo reescrito com os seis gatilhos da Folloni
