Cursor · live apps · @cursor_ai

O Cursor agora constrói o app, sobe o database e te devolve um link pra compartilhar

A promessa é sair do localhost de uma vez: você descreve a ferramenta, o cloud agent monta, passa por security checks e publica um endereço vivo para o time.

Quinta · @cursor_ai · cerca de 304 mil impressões e 2,9 mil likes

A conta oficial do Cursor (@cursor_ai) anunciou o Build Live Apps: em vez de deixar o protótipo preso na sua máquina, você pede a um cloud agent que construa o app, configure um Postgres se precisar, coloque autenticação atrás do Cursor SSO e faça o deploy. Na hora de publicar, você escolhe um domínio único, o Cursor roda checagens determinísticas e agentic de segurança, e só então devolve o link ao vivo. Nada sobe sem os checks passarem e sem você apertar Publish de propósito.

No vídeo de lançamento, o exemplo é um seat map para acomodar novos contratados: o agente monta o floor plan, a lista de hires e o preview no browser, e o modal de Publish deixa claro quem pode abrir o app, se é só a dona, o time ou a empresa inteira. Em planos individuais também dá para compartilhar em público, e ainda dá para provisionar uma API key do Cursor se um script ou um Grok Bot precisar usar a ferramenta. A capacidade já está nos planos pagos com cloud agents ligados, e o deploy sai de repos novos ou existentes no Cursor Origin e no GitHub.

O recado de fundo é bem direto. Agents baratearam escrever código, mas a maior parte das ferramentas internas nunca saía do localhost; agora qualquer pessoa de ops, vendas, jurídico ou engenharia descreve o que precisa e manda o link para o colega. Se um check de segurança falhar, o agente lista o que corrigir antes de tentar de novo, e os admins do time veem cada app e cada secret publicados.

Hora do Hands-on

três testes de dez minutos · pra sexta
teste 1 · live app

Peça ao Cursor um app miúdo e compartilhe o link

Num plano pago com cloud agents ligados, peça explicitamente para construir um app simples, como uma lista de presença ou um contador de ideias do time. Publique, copie o link e mande para uma pessoa: o teste vale se ela abrir sem você precisar explicar o localhost.

teste 2 · workflow

Leia a thread do @xikhar e anote a ordem da stack

Abra o post (1/7) e percorra a thread marcando o que veio primeiro: conceito, imagens, modelos 3D, Blender ou Three.js. Em dez minutos você sai com um checklist próprio para o próximo protótipo de jogo ou cena interativa.

teste 3 · Sumiro

Jogue os primeiros dez minutos do Sumiro no browser

Entre em xikhar.github.io/sumiro, comece um New Game e preste atenção no que a stack de IA entregou de fato: controle, câmera, arte e ritmo. Anote um ponto que surpreendeu e um que ainda parece feito por bot.
